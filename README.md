# SupportLens — AI Support Assistant

Рабочий MVP поддержки вымышленного интернет-магазина **Qala Market** в Казахстане.
Интерфейс на русском, есть обращения на казахском и со смешением языков.
**Все начальные обращения, магазин и правила — вымышленные.** Это не реальные правила торговли и не юридическая консультация.

## Запуск

Нужен Python 3.11+ и доступ в интернет только для первой установки зависимостей.
После установки деморежим работает без интернета.

Windows PowerShell, из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Можно также выполнить `powershell -ExecutionPolicy Bypass -File .\run.ps1`.
Этот скрипт использует локальное `.venv`, а если его нет, создаёт окружение и устанавливает зависимости.
На этом компьютере он умеет использовать Python из среды Codex, даже если `python` не добавлен в PATH.

macOS / Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

Открыть **http://localhost:8501**. Сервер доступен только на этом компьютере.
Остановка — `Ctrl+C` в терминале запуска. Для другого порта добавьте `--server.port 8502`.

## Возможности

- **Обращения:** добавление сообщения, фильтры по теме/приоритету/статусу, поиск, карточка обращения и история действий.
- **Анализ:** шесть тем, четыре приоритета и объяснения. Оператор может исправить тему и приоритет; источники и черновик пересобираются локально.
- **База знаний:** 15 содержательных статей `KB-001`–`KB-015`; видны точные полные абзацы источников.
- **Ответ:** подтверждённые материалы, сведения для уточнения, рекомендуемое действие, редактирование, сохранение и утверждение. Реальной отправки клиенту нет.
- **Аналитика:** количество, темы, приоритеты, динамика по дням UTC+5, отсутствие инструкции, доля утверждений и фактическое время обработки. Есть переключатель между всеми, демонстрационными и добавленными обращениями.
- **SQLite:** 50 начальных обращений загружаются один раз, вместе с 8 явно обозначенными демонстрационными утверждениями. Изменения и журнал сохраняются между запусками.

Критический приоритет предусмотрен для возможного захвата аккаунта и угрозы безопасности товара.
Возможное двойное списание получает высокий приоритет независимо от тона. Эмоции и слово «срочно» сами по себе приоритет не повышают.
Оператор может исправить результат; если он понижает приоритет относительно правила риска, карточка показывает предупреждение.

## Подключение AI

По умолчанию ключ отсутствует и работает **«Демо без AI»**: правила, поиск по ключевым словам и шаблон с цитатами. Это не работа языковой модели.

Скопируйте `.env.example` в `.env` и задайте:

```dotenv
AI_API_KEY=ваш_ключ
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4o-mini
AI_TIMEOUT_SECONDS=20
SUPPORTLENS_DB=data/supportlens.sqlite3
```

Перезапустите сервер. Можно передать эти же значения через переменные окружения — они имеют приоритет над `.env`.
Файл `.env` исключён из Git; секреты не показываются в интерфейсе и сообщениях об ошибках.
Нужен доступ к модели с поддержкой **Chat Completions + `response_format: json_schema`**.
Адрес задаётся до `/chat/completions`. Удалённый API должен использовать HTTPS; HTTP разрешён только для localhost.
Модель и API можно заменить на совместимый сервис. Неподдерживаемая схема API приведёт к явному переходу на деморежим.

Реализация следует [официальной документации OpenAI о Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Обработка использует два запроса: классификация и подбор статей по каталогу, затем выбор точных абзацев по полным текстам и плана ответа.
Модель выбирает материалы, язык приветствия, сведения для проверки и действие. Итоговый черновик собирается из выбранных **проверенных полных абзацев**, безопасного приветствия и вопросов.
Свободный непроверяемый текст модели не превращается в факты клиентского ответа. Такой подход ограничивает стиль, зато исключает новые обещания и вымышленные сроки в автоматически созданном черновике.

Проверяются структура, допустимые темы/приоритеты/действия, поля уточнения, существование идентификаторов и совпадение цитат с полными абзацами.
Правила риска применяются поверх результата модели. Инструкции клиента передаются как данные и не дают модели доступа к базе, секретам или отправке сообщений.
Таймаут одного запроса ограничен 1–60 секундами; максимум два запроса на обращение.
При ошибке подключения, HTTP, таймауте, обрыве соединения, некорректном JSON или неподтверждённой цитате частичный AI-ответ отбрасывается целиком.
Обращение уже сохранено, затем создаётся черновик по локальным правилам и карточка явно показывает ошибку и деморежим.
Начальные данные всегда обрабатываются локально и не расходуют API. Проверяйте AI на новом обращении или кнопкой «Повторить анализ» в неутверждённой карточке.

## Данные и расчёты

По умолчанию база хранится в `data/supportlens.sqlite3`. Для резервной копии остановите сервер и скопируйте этот файл.
`SUPPORTLENS_DB` позволяет использовать отдельную базу; относительный путь отсчитывается от папки проекта.
Демонстрационная загрузка защищена транзакцией и отметкой версии, повторный запуск не добавляет копии и не заменяет сохранённые ответы.

- Доля утверждённых = число текущих утверждённых ответов / число обработанных обращений. Необработанные обращения исключены из знаменателя.
- «Без инструкции» = обработанные обращения без источников, включая вопросы вне базы. Это не означает автоматически «без решения».
- Среднее время AI = фактическое время успешных запусков с `mode=ai`, включая API-запросы и проверку. Если их нет, показано «Нет вызовов».
- Ошибки API и время неуспешных попыток показаны отдельно. Среднее всей обработки включает демо, AI и переходы на демо, исключает загрузку базы и ручные правки.
- Повторные обработки учитываются отдельными запусками; количество обращений от этого не растёт.
- Правки черновика, классификации и рабочего статуса снимают прежнее утверждение. Утверждённые тексты сохраняются в истории действий.

## Трёхминутная демонстрация

1. **0:00–0:30.** Покажите название магазина и отметку «Демо без AI». Объясните: данные вымышлены, помощник готовит ответ оператору, решение принимает человек.
2. **0:30–1:15.** Раскройте «Новое обращение», введите: `За заказ 5170 деньги списали два раза. Проверьте, пожалуйста.` Нажмите «Добавить и обработать». Покажите высокий приоритет, объяснение финансового риска, источник `KB-003`, вопросы и передачу специалисту. Возврат денег не обещается.
3. **1:15–1:45.** Допишите в черновике уточняющий вопрос о датах операций и нажмите «Утвердить ответ». Покажите сохранённый статус и отсутствие реальной отправки.
4. **1:45–2:15.** Откройте «Аналитика», переключите на добавленные оператором обращения: новое обращение учтено, доля утверждений обновилась. Среднее AI честно показывает отсутствие вызовов, если ключ не настроен.
5. **2:15–2:45.** Покажите поиск `KB-011` в базе и пример захвата аккаунта в очереди. Сравните с эмоциональным вопросом о размерах: эмоции не поднимают приоритет.
6. **2:45–3:00.** Добавьте `Можно оплатить криптовалютой?`: нет инструкции, нужен специалист. При наличии ключа покажите пометку AI на новом обращении; без ключа объясните, что API подключается через `.env`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты изолированы от рабочей базы. Проверяются риски и эмоции, казахские сообщения, неизвестные вопросы, попытки внедрения инструкций,
все цитаты демоданных, некорректные идентификаторы и JSON, таймаут и HTTP-ошибка, схема и разделение ролей запроса,
сохранение и повторная загрузка, отсутствие дубликатов, исправление классификации, снятие утверждения, расчёты и фильтры аналитики.
Streamlit AppTest проходит виджеты трёх разделов и полный сценарий нового обращения → черновик → редактирование → утверждение → аналитика → новая сессия.
Первый тест интерфейса может занять до минуты на холодной загрузке зависимостей.
API проверяется контролируемыми ответами и ошибками. **Реальный вызов модели без ключа не проверен.**

## Ограничения MVP

Это локальный инструмент одного оператора: нет авторизации, клиентских каналов, внешнего каталога и проверки реальных заказов или банковских операций.
Локальная классификация использует ключевые слова и может ошибаться на сложных формулировках и отрицаниях; есть ручная корректировка.
Поиск ограничен 15 статьями. AI может ошибиться в релевантности существующего источника, поэтому оператор проверяет применимость перед утверждением.
Казахские и смешанные обращения поддерживаются правилами; политика в базе и основная часть черновика остаются на русском, AI может выбрать казахское приветствие.
Редактируемый оператором текст не проходит семантическую проверку обещаний: ответственность за ручные правки и утверждение остаётся у оператора.
API отправляет сообщение клиента выбранному провайдеру; для демонстрации используйте вымышленные данные.
Нет автоматического обновления остатков, выполнения действий, метрик удовлетворённости и оценки экономии времени.

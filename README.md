# SupportLens — AI-помощник поддержки

Локальный MVP на Python, Streamlit и SQLite для вымышленного магазина **Qala Market**. Начальные обращения и правила вымышленные. Помощник готовит ответ оператору; сообщения клиентам и действия с заказами не выполняются.

## Запуск

Python 3.11+, затем из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1
```

Либо `powershell -ExecutionPolicy Bypass -File .\run.ps1`. Скрипт создаёт локальное окружение при необходимости; на этом компьютере также находит Python среды Codex. На macOS/Linux используйте `python3` и `.venv/bin/python`.

Открыть [localhost:8501](http://localhost:8501). `Ctrl+C` останавливает сервер; `--server.port 8502` меняет порт. После первой установки локальный режим работает без интернета.

## Подключение модели

Скопируйте `.env.example` в `.env`. Пример Groq, без настоящего ключа:

```dotenv
AI_API_KEY=ваш_локальный_ключ
AI_PROVIDER=Groq
AI_BASE_URL=https://api.groq.com/openai/v1
AI_MODEL=openai/gpt-oss-20b
AI_RESPONSE_FORMAT=json_schema
AI_TIMEOUT_SECONDS=30
AI_TOTAL_TIMEOUT_SECONDS=60
SUPPORTLENS_DB=data/supportlens.sqlite3
```

Поддерживается другой совместимый **Chat Completions** API. Адрес задаётся до `/chat/completions`; удалённый API требует HTTPS, HTTP разрешён только для localhost. Для провайдера без строгой схемы можно выбрать `AI_RESPONSE_FORMAT=json_object`: локальная проверка структуры остаётся обязательной.

Настройки читаются заново из `.env`, переменные окружения имеют приоритет. В разделе **«Подключение AI»** нажмите «Обновить настройки», затем «Проверить соединение». Проверка отправляется только по явному нажатию. Начальная загрузка, навигация и обновления страницы не вызывают модель.

Состояния: **AI не настроен**, **подключение не проверено**, **модель успешно ответила**, **ошибка AI** с категорией авторизации, лимита, соединения или формата. Непустой ключ не считается подтверждением работы. Последний успех не гарантирует успех следующего запроса; карточка отдельно показывает, кем создан текущий ответ.

`.env`, окружение, SQLite и логи исключены из Git. Ключ не отображается и не сохраняется в истории: для сопоставления настроек хранится только хеш. Ошибки заменяются безопасными описаниями без исходного тела ответа провайдера. Для демонстрации используйте вымышленные сообщения: API передаёт их выбранному провайдеру.

## Возможности

- **Очередь:** фильтры, поиск, сортировка; сначала неутверждённые критические и высокие обращения. Нажатие строки открывает карточку. Новое обращение открывается независимо от старых фильтров.
- **Анализ:** тема, приоритет, язык ru/kk, известные сведения, необходимые уточнения и отдельные рекомендации оператору. Отрицания и гипотетические риски отличаются от текущих инцидентов; сумма не считается номером заказа. Возможное двойное списание получает высокий приоритет, признаки захвата аккаунта и опасности товара — критический.
- **Черновик:** естественный ответ модели по найденным материалам, целиком на русском или казахском. Общий вопрос о стоимости доставки не требует номера заказа. Известная часть смешанного вопроса сохраняется, неизвестная обозначается отдельно.
- **AI-помощник:** пять быстрых вопросов, свободный вопрос и отдельный сохранённый диалог каждого обращения. Источники показаны рядом. Предложенный ответ применяется только кнопкой оператора, затем утверждается отдельно.
- **Версии:** сохранение, утверждение, история ответов и загрузка предыдущей версии в редактор. Ручная корректировка классификации сохраняет текст и утверждение; генерация — отдельное действие с предупреждением. Несохранённые правки остаются в буфере сессии при навигации и фильтрах.
- **База знаний:** 15 начальных статей, поиск, создание и редактирование. Версии и точные снимки источников сохраняют проверяемость старых ответов после изменения статьи.
- **Аналитика:** период и набор данных, переходы к обращениям; успешные AI-запуски, локальные обработки и ошибки с резервным ответом показаны отдельно. Доля утверждений означает состояние работы оператора, а не точность AI.

## Проверка AI-ответов

Обработка: классификация и извлечение сведений → выбор материалов и генерация → дополнительная проверка фактов моделью. Модель выбирает ключи абзацев; точные цитаты загружает сервер. Текст клиентского ответа пишет модель, а не шаблон из цитат. Приложение добавляет необходимые вопросы о неизвестных сведениях.

Сервер проверяет JSON, допустимые поля, доказательства извлечения, существование и релевантность статей, точность цитат, связь сегментов с источниками, числовые значения, включённость границ условий, язык и неподтверждённые действия. Дополнительный запрос проверяет условия и смысл. Схема и проверка моделью **не гарантируют** отсутствие ошибок: оператор отвечает за применимость и ручные изменения. См. [документацию OpenAI о Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [документацию Groq](https://console.groq.com/docs/structured-outputs).

Если провайдер отклонил строгий JSON с `json_validate_failed`, допускается одна попытка JSON-mode в оставшееся время, с теми же проверками. Лимиты 429 и ошибки авторизации автоматически не повторяются. Один запрос ограничен 1–60 секундами, общий сценарий — 1–120. При ошибке весь частичный ответ отбрасывается; сохранённое обращение получает явно обозначенный резервный ответ. Без ключа работают локальные правила и русские/казахские шаблоны; диалог модели не имитируется.

## Сохранность и расчёты

SQLite находится в `data/supportlens.sqlite3`; относительный `SUPPORTLENS_DB` отсчитывается от папки проекта. Для резервной копии остановите сервер и скопируйте базу.

Миграции добавляют поля и таблицы без замены сообщений, ответов, утверждений и журнала. 50 начальных обращений и 8 помеченных демоутверждений загружаются один раз. Изменённые статьи не перезаписываются.

Обращение фиксируется до внешнего запроса; токен формы защищает от повторного добавления. Версия записи проверяется при анализе, сохранении и применении предложения. Если другой сеанс сохранил или утвердил ответ, устаревший результат отклоняется с уведомлением. Буфер несохранённого текста живёт только в сессии браузера; перед закрытием вкладки сохраните черновик.

Доля утверждений = текущие утверждённые / обработанные обращения. «Без инструкции» — обработанные вопросы о компании без источников; самостоятельные общие ответы не считаются пробелами базы. Среднее AI учитывает успешные запуски; время ошибок отдельно. Повторный анализ добавляет запуск, не обращение. Период применяется к дате UTC+5: обращениям по дате создания, запускам по дате обработки.

## Трёхминутная демонстрация

1. **0:00–0:25.** Откройте «Подключение AI», покажите модель и выполните проверку. Магазин и данные вымышленные, ключ остаётся локально.
2. **0:25–1:05.** Добавьте: `За заказ 5170 деньги списали два раза по 18000 тенге сегодня. Проверьте, пожалуйста.` Покажите этапы, AI, высокий приоритет, найденные сведения, KB-003 и естественный ответ. Номер заказа, сумма и дата не спрашиваются повторно.
3. **1:05–1:40.** Спросите «Почему такой приоритет?», затем «Сделай ответ короче». Проверьте предложение, примените к черновику и утвердите. Отправка не выполняется.
4. **1:40–2:10.** В аналитике выберите сегодняшний день и добавленные обращения; покажите AI отдельно от ошибок и локальных обработок. Откройте обращение из аналитики.
5. **2:10–2:40.** Добавьте `Сколько стоит доставка в Алматы?`: стоимость по KB-004 без лишних вопросов. В помощнике запросите казахский ответ.
6. **2:40–3:00.** Покажите версию источника, историю и базу знаний. При лимите провайдера покажите явный резервный режим, не выдавая его за AI.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

81 автоматический тест используют временные базы и подставные API без рабочего ключа. Проверены прежние сценарии, отрицания/гипотезы, извлечение чисел, ru/kk/смешанные сообщения, неизвестные вопросы, внедрение инструкций, факты и цитаты, таймауты/HTTP/JSON-mode, миграция старой схемы, конфликты сохранения и утверждения, отдельные диалоги, версии источников, период аналитики, несохранённый текст и новое обращение при исключающих фильтрах. Streamlit AppTest проходит реальные виджеты.

Реальные запросы отдельно проверялись через **Groq / openai/gpt-oss-20b** на вымышленных обращениях о доставке и двойном списании. Успешные русские и казахские ответы и диалог помощника сохранены как AI. Также воспроизведён реальный лимит 429 с переходом на резервный режим. Явное повторение (расходует квоту):

```powershell
.\.venv\Scripts\python.exe scripts\live_check.py payment
.\.venv\Scripts\python.exe scripts\live_check.py delivery
.\.venv\Scripts\python.exe scripts\live_check.py kazakh
.\.venv\Scripts\python.exe scripts\live_check.py assistant
```

Скрипт печатает результаты только заданных вымышленных примеров, не ключ; токены предотвращают дубликаты. Повторный запуск анализирует то же обращение. Подставные тесты или прежний успех не подтверждают текущую доступность провайдера.

## Общие вопросы и основания ответа

Модель разделяет вопрос по смыслу на общую часть и часть о компании. Арифметика, определения, перевод и объяснения допускают собственные знания ИИ. Оплата, доставка, цены, возвраты, гарантия и наличие требуют подтверждённых статей, даже если вопрос кажется простым.

В карточке и диалоге отмечены основания:
- **Общий ответ ИИ** — общие знания, не правило Qala Market.
- **По базе знаний** — существующие статьи, полные цитаты, снимки версий и рабочие постоянные ссылки вида `?article=KB-007`.
- **Нужна проверка** — конкретное отсутствие сведений. Отсутствие наличных в неполном перечне способов оплаты не считается запретом.

Смешанный ответ сохраняет обе части. Справочный вопрос о сроке возврата не требует номера заказа или фотографий. Модель не может создать скидку по команде клиента. При технической ошибке появляется отдельное сообщение и явный резервный режим. Без ключа общий ответ модели не имитируется.

В AI-помощнике можно спросить о текущем обращении или задать независимый общий вопрос. Используются только текущая карточка и последние десять сообщений её истории. Простой общий ответ не заменяет клиентский черновик. Изменение черновика происходит только после явной просьбы и нажатия «Применить к черновику». После ошибки доступна кнопка «Повторить запрос».

Четыре кнопки навигации имеют единые Material-иконки, активное состояние, наведение и фокус с клавиатуры. На узком экране меню раскрывается штатной кнопкой Streamlit. Индикатор «Подключён» появляется только после успешной проверки или ответа; ошибка последнего запроса отображается отдельно. После изменения настроек прежний успех другого подключения не используется.

Проверки нового поведения включают общий/корпоративный/смешанный ответ, отсутствующую статью, вымышленные цитаты и скидки, неподтверждённый запрет наличных, ошибку API, работу без ключа, историю диалога, сохранение оснований и повтор запроса. Браузер проверен на ширине 1440 и 390 px. Реальный Groq ответил «4» на `2 + 2`; определение банковской карты проверено через панель помощника. Также проверен смешанный вопрос о возврате с KB-007. Лимит 429 воспроизведён реально: доступность модели зависит от квоты.

```powershell
.\.venv\Scripts\python.exe scripts\live_check.py general
.\.venv\Scripts\python.exe scripts\live_check.py definition
.\.venv\Scripts\python.exe scripts\live_check.py cash
.\.venv\Scripts\python.exe scripts\live_check.py mixed
.\.venv\Scripts\python.exe scripts\live_check.py missing
.\.venv\Scripts\python.exe scripts\live_check.py injection
```

Каждый запуск выполняет реальные запросы и расходует квоту; не запускайте все сценарии подряд при низком лимите. Перед демонстрацией проверьте соединение один раз. Общие знания модели могут быть неточными или устаревшими; поиска в интернете нет. Ручные изменения ответа требуют проверки оператором.

## Ограничения

Нет авторизации, отправки клиентам, внешнего каталога и проверки заказов/операций. Поиск комбинирует смысловой выбор статей моделью и ключевые слова. Ошибка выбора или оценки фактов возможна. Локальный текст для изменённой или новой статьи требует участия специалиста и не выдаёт старый шаблон за новые правила. Проверка не заменяет оператора. Доступность зависит от сети и квоты. Нет вымышленных метрик экономии времени или удовлетворённости.
